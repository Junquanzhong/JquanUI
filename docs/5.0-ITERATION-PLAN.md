# JquanUI 5.0 迭代方案

日期：2026-10-08。状态：基于当前工作区代码的提案，以下新入口、新 API 和指标目标尚未实现。

建议定位：**兼顾直接脚本使用与生产构建的原子 UI 框架，让样式、交互、主题和 AI 开发遵循同一套可验证契约。**

5.0 的核心价值是让现有能力更易组合、更易维护、更可靠地交付。保留语义原子类、直接 script 引入、运行时动态编译、构建提取和无框架依赖这些优势。组件和 Data 继续独立于 CSS Core。

## 1. 当前实现与可保留的优势

| 领域 | 阅读到的实现 | 5.0 的起点 |
| --- | --- | --- |
| 原子引擎 | `dist/core/JquanUI@Core.js`：字典、主题、变体、插件、解析、排序、CSSOM、缓存、扫描与生命周期集中在一个 IIFE | 抽出共享编译器，保留现有语法与兼容入口 |
| 样式一致性 | canonical utility order、物理方向 shorthand/longhand 排序、可选 cascade layers | 建立 runtime/build/SSR/ShadowRoot 的同一组契约测试 |
| 动态能力 | MutationObserver、idle 分片、精确 `prefetch()`、Constructable Stylesheet、`adopt()` / `detach()` | 改进调度与长生命周期应用的资源管理 |
| 现代 CSS | 容器查询、关系/属性/任意变体、现代颜色、流体令牌、Safe Area；发布记录还列出 Anchor 与 View Transitions 扩展 | 先消除源码与产物分叉，再按真实使用场景补齐 |
| 生产工具 | CLI、Vite、PostCSS、Baseline 拆分、迁移审计、tokens、SSR 薄适配 | 共享纯编译器、文件级增量提取与可定位诊断 |
| 组件 | manifest 注册 77 个独立文件；包含 UI、服务、预设和组合能力 | 优先统一底层与高频组件，再选择新组件 |
| 文档 | `content/` 62 个顶层模块；`content/components/` 77 个文档模块和一个 index；公共 Template 片段 | 让文档、示例、类型、skill 消费同一份能力元数据 |
| Data | 独立 `jquanui/data`，版本仍为 0.2.0；有 schema、迁移、持久化、Outbox、同步恢复 | 单独制定稳定化标准，与 5.0 Core 解耦演进 |

主要阅读范围：Core 解析器与插件/扫描/缓存/公开 API；extract、Vite、tokens、SSR 入口与类型；Table、Select、Tree、Dialog、Popover、UI/Overlay Preset、QuickActionLauncher 的代表性实现；组件 manifest、文档模块、检查脚本、README、ROADMAP、CHANGELOG 和项目 skill。组件结论来自这些代表性模块，尚未逐一执行全部 77 个组件的浏览器行为。

## 2. 已验证的基线问题：应排在新功能之前

| 检查或观察 | 本次结果 | 对迭代的影响 |
| --- | --- | --- |
| `node scripts/check-version.cjs` | 已修复：package、正式 Core、Full、压缩 Core 与 CLI 均为 4.72.0；v4.5.3 仅保留为归档入口 | 发布版本元数据与正式运行时一致 |
| `node scripts/check-core-regressions.cjs` | 退出 1：`view-transition-group-nearest should resolve to view-transition-group: nearest` | 源码缺少已在当前回归中要求的能力 |
| 设置 `JQUAN_CORE_PATH=js/JquanUI@core.min.js` 后执行同一回归 | 退出 0：`[JquanUI] core regression check ok` | 压缩 Core 与源码行为不同；不能直接拿旧源码重建覆盖产物 |
| `node scripts/build-component-bundles.cjs --check` | 退出 1：`Full bundle is stale` | Full 聚合产物存在分叉 |
| `node scripts/check-component-documentation.cjs` | 退出 1：`Example/code source drift: select.js` | Select 的 `examples[0].code` 与 `declarative` 不一致 |
| `node scripts/check-documentation.cjs` | 退出 0：`[JquanUI] documentation check ok (14 public APIs)` | 通用文档闸门已存在，但覆盖面仍需扩展 |
| `node scripts/check-types-surface.cjs` | 退出 0：`[JquanUI] types surface check ok` | 当前类型表面符合现有检查，并不代表所有组件已有精确类型 |

补充观察：

- `dist/browser-globals.d.ts` 对 favicon、iframeBridge 有具体类型；其他组件落入 `[key: string]: unknown`。Table 等高频 API 值得优先补齐。
- Core 目前共 4473 行，源文件 265549 bytes；现有压缩文件 155764 bytes，gzip 40268 bytes。由于源码与产物分叉，这些数字分别描述文件，不能视为同一次构建的压缩比。
- `reports/core-performance.json` 是 2026-09-07 的历史报告，标记为 4.72.0，3 个样本。本次未重跑性能基准；历史结果不代表当前分叉源码的表现。
- 当前 `getMetrics().cacheHitRate` 由 cache hydrate 的 hit/miss 转为 1/0，并非逐次解析的缓存命中率。5.0 应明确两种指标的含义。
- npm components 子路径走 browser/global 注册入口；Core 安装依赖需要显式先后调用。现有机制可继续兼容，但不足以替代真正的组件 ESM 导出和依赖装配。

基线修复应通过语义对账恢复完整、可维护源码，再从唯一源生成所有产物。旧压缩文件可以作为行为对照，恢复完成以全量回归和产物一致性检查为准。

## 3. 主线 A：共享编译器与模块化工程（P0）

### A1. 将源码与生成产物分离

建议逐步引入 `src/compiler/`、`src/runtime/`、`src/components/`、`src/presets/`、`src/tooling/`。继续生成现有 `dist/core/JquanUI@Core.js`、压缩 Core、Components 和 Full 兼容文件。

先迁移文件组织和构建关系，使用旧行为对照测试；随后才调整算法。版本、组件清单、能力清单、生成类型和产物哈希由统一构建流程管理，减少手工同步。

### A2. 抽出无 DOM 的共享编译器

当前 extractor 的 `createRuntime()` 会用 Node `vm` 执行浏览器 Core，并提供模拟 document、CSSOM、Observer 和计时器。这复用了 Core，避免了两套规则，但也让构建工具受浏览器初始化流程牵制。

提议抽出统一管线：

`类名词法分析 → 变体/工具解析 → 规则中间表示 → canonical 排序 → CSS 输出`

规则中间表示保存 selector、声明、at-rule、排序键、来源与诊断。浏览器 runtime 负责扫描与注入；CLI/Vite/PostCSS/SSR 直接调用编译器。插件映射与排序规则仍只有一份。

提议新增 `jquanui/compiler` 纯 ESM/CJS 入口。此入口不读取 DOM 或 localStorage。旧 `createRuntime(coreFile, options)` 保留兼容过渡，旧插件通过适配层接入。

**验收：** runtime、构建、SSR、ShadowRoot 对同一语料生成等价规则和级联结果；覆盖任意值转义、嵌套变体、important、现代颜色、shortcuts、插件、逻辑与物理方向冲突。测试比较最终样式和规则结构，不只比较字符串。

## 4. 主线 B：更轻的生产模式与增量构建（P0/P1）

### B1. 明确三种使用模式

| 提议模式 | 场景 | 行为 |
| --- | --- | --- |
| runtime | 直接 script、动态原型、无构建项目 | 保留自动扫描与动态编译 |
| static | 类集合在构建时已确定的站点 | 发射 CSS，样式引擎无需进入浏览器；组件按需使用独立运行时 |
| hybrid | SSR、路由懒加载、存在动态类的应用 | 首屏使用已提取 CSS，运行时补充未覆盖类 |

这些是 5.0 提议中的模式，而非当前配置值。Hybrid 建议使用带 compiler/config/plugin 版本哈希的类与规则 manifest；哈希失配时忽略旧清单并重新编译，确保动态内容样式正确。

组件运行时独立化必须先完成，才能让依赖 `JquanUI.use()` 的组件在 static 模式中正常增强。构建器提取组件所需样式与其显式声明的完整动态类，复杂值继续采用现有任意值通道。

### B2. 文件级增量提取

当前 Vite `handleHotUpdate()` 对匹配源文件调用 `buildCss(true)`，重新遍历配置输入。建议引入 `file → classes` 索引和类引用计数：修改只更新一个文件；删除文件移除引用；新增文件由 watcher 纳入；配置或插件变化执行全量失效。

现有字符串/平衡括号扫描保持轻量默认；为复杂 JSX/TSX/Vue/Svelte 表达式提供可选 AST 适配器。动态拼接给出文件位置和显式映射/safelist 建议。补 source map 与“这条 CSS 来自哪些文件”的诊断。

**验收：** 在 100、1000 文件夹具中比较冷构建和单文件更新；新增/删除/重命名、共享类引用、配置热更新、插件函数变化均正确；增量与全量结果相等。目标是在同环境中将 1000 文件单文件更新 median 降低至少 50%，该数值是待验证目标。

## 5. 主线 C：运行时调度与可观测性（P1）

- 保留已有 idle 分片、Observer 批处理和 `prefetch()`，增加按时间预算调整任务大小；首屏已知类同步完成，后续低优先级任务分片执行。
- 当前 `insertDynamicRule()` 使用 `findIndex()` 和数组 `splice()` 插入排序规则。先测规则数量增长曲线，再评估二分查找与合批插入；二分查找不能消除 splice/CSSOM 成本，收益以基准为准。
- 为纯编译结果建立有上限缓存，key 覆盖 compiler、配置及插件版本。明确未解析类在 `addUtility()` 或插件安装后如何失效，避免错误被长期记忆。
- 区分 `cacheHydrate`、`resolveCacheHits/Misses`、队列等待、实际解析、规则注入和 CSSOM 失败。高成本来源追踪保持开发模式 opt-in。
- 定义实例级 `destroy()` 契约：取消未完成队列、断开 document/ShadowRoot Observer、释放插件监听和实例引用；测试连续挂载/卸载与异步迟到结果。
- 规则回收先作为长生命周期应用实验；只有证明不破坏其他 root、路由缓存、插件动态类和 shared sheet 才开放。5.0 首版不因“省规则”引入不可预测缺样式。

**验收：** 重跑现有六类真实 Chromium 基准，增加 5000 个唯一类、持续变更、路由切换和 100 次销毁场景。设定同机 median 不回退超过 10% 的候选门槛，并通过重复样本确认噪声；公开记录包体、内存、长任务与正确性。

## 6. 主线 D：组件基础设施与高频组件（P0/P1）

### D1. 独立组件运行时与 ESM

提议建立组件级 runtime，负责依赖拓扑、幂等安装、root 作用域、实例注册、事件清理和异步取消。新 ESM 入口直接导出插件/API/类型；旧 `JquanUIComponents.*` 和 `JquanUI.use()` 经适配层保持可用。

组件依赖分为 required、optional、style preset。当前 Table 的文档建议先装 Pagination，而源码 `requires: []`；5.0 应准确表达“配置分页时需要 Pagination”，并对缺少能力给出可定位诊断。

### D2. 统一浮层与交互底层

当前 Dialog 有独立 scroll lock 和 focus helper，Popover、Select 各有定位/焦点代码；`overlayPreset` 主要共享样式。建议建立独立于 Core 的 OverlayManager，集中管理堆叠、Escape、点击外部、焦点恢复、嵌套滚动锁、portal 与定位。

原生 dialog/popover/Anchor Positioning 作为支持环境中的实现路径；旧环境使用测量定位适配。Dialog/Modal/Drawer、Dropdown/Popover/Tooltip、Select、DateTimePicker 分批迁入。已有键盘逻辑继续保留并补组合回归。

### D3. 优先级与验收

| 顺序 | 能力 | 复用与演进方式 | 核心验收 |
| --- | --- | --- | --- |
| 1 | Table 2.x 补强 | 先完善原 Table：远程取消、request 序号、明确 error 状态、排序按钮与 `aria-sort`、筛选焦点保持 | 慢旧请求不覆盖快新请求；destroy 后结果不重新渲染；全部排序可用键盘操作 |
| 2 | Select / Tree | Select 增加远程搜索和取消、完整 combobox/listbox 状态；Tree 补键盘导航、展开状态、异步节点 | 原生表单值同步；方向键/Home/End/Escape 行为明确；中英文与 RTL 可用 |
| 3 | 共享 virtualizer + VirtualList | 为 Table/Tree/Select 共用可选窗口化；先固定高度，再研究动态高度 | 10000 项渲染节点随视口而非总项数增长；滚动锚点、选择、焦点不丢失 |
| 4 | 命令面板 | 优先扩展现有 QuickActionLauncher 的命令注册、快捷键、分组和 OverlayManager 组合 | 路由命令与动作复用现有服务；快捷键退出、权限显示与销毁有测试 |
| 5 | SplitPane | 可新增独立通用组件，支持拖拽/键盘调整、min/max、折叠、容器布局 | 触控与键盘均可调整；动态测量留在内部；尺寸持久化复用 Storage |

VirtualList 的可访问性要明确窗口化限制；提供非虚拟模式，并验证聚焦项和屏幕阅读器语义。Table 的列固定/调整/行展开列为下一批；先修复请求和交互契约，再增加复杂网格行为。

业务组合组件继续消费 HTTP、Storage、Store、Permission、i18n、Data 和基础 UI API。新增能力前必须明确 API 归属；RichText、图表、流程编辑器等大依赖组件留待独立评估。

## 7. 主线 E：主题、预设与类型（P1）

### E1. 让组件预设消费主题令牌

Core 已有 semantic themes 和 `setTheme()`；UI/Overlay Preset 与 Table 的代表性默认值仍大量使用 white/slate/blue。建议定义 surface、surface-muted、text、text-muted、border、accent、focus 等角色令牌，以及 compact/comfortable 密度尺度。

渐进替换默认样式，并保留公开 `classes` 覆盖与旧预设。切换主题更新变量即可，避免重建组件 DOM。组件局部主题沿 root/ShadowRoot 继承，不扩散到整个页面。

2026-10-15 纵向切片：新增 `jquan-migrate --dark-audit --source` 只读审计与 `auditDarkSource()` / `auditDarkFiles()` API。报告硬编码颜色、固定阴影、语义角色和缺少 dark 变体，`--max-dark-missing` 可作为 CI 阈值；不会自动重解释历史颜色或改写业务文件。已同步 CLI README、README、类型、skill 与 migrate 回归。

同日收尾：补齐 migrate 子路径 ESM/类型，配对按属性、important 与非 dark 有序变体链核对，支持变体组、显式任意颜色和自定义角色名；修复 hover/断点互相掩盖与等号阈值解析。报告以每文件唯一 class 字符串为单位，动态表达式、shortcut、独立 CSS 和最终对比度仍需人工检查。下一步为 Overlay Preset 和分页等组件的语义角色迁移，旧颜色自动映射仍属提案。

2026-10-15 后续切片：Overlay Preset 新增 semantic/legacy 模式（overlay 缺省继承 ui），Msg/Toast 共享外观、Popover 箭头与 Pagination 基础样式已消费角色变量，Tooltip 保持反色。运行时切换变量保留 DOM/焦点/页码；状态色显式 dark，遮罩/阴影固定。Modal 表单与 Select/NumberInput 增强样式仍待迁移。当前同步冲突文件导致清单/文档索引检查失败；Full 的分页语言标签与独立源码已有分叉，本轮仅同步其样式块，保留其余内容。

2026-10-15 入口一致性切片：Core、压缩 Core、Full 和 Components 均嵌入同一 `JquanUI.import()` 导入器。导入器按 manifest 解析本地组件、递归装配依赖、去重并支持 `baseURL/timeout/install/nonce`；补齐 OverlayManager 依赖、非法 URL/nonce 错误码和组件构建排除同步冲突的 `-DESKTOP-*` 备份文件。组件导入单元与浏览器回归通过。

2026-10-15 发布清理切片：npm 发布清单排除未被 exports 引用的 `DESKTOP` 冲突副本、旧 demo、发布摘要、开发期 manifest、重复的 `dist/cli/README.md` 和旧 4.5 压缩副本；`check-size` 与 manifest 使用相同排除规则。根 README 保留随包可用的 CLI/Vite/PostCSS/SSR 文档，预算阈值保持不变。

2026-10-15 版本对账切片：正式 Core 的 `ENGINE_VERSION` 从 4.70.0 对齐到 package 的 4.72.0，随后重建压缩 Core 与 Full；归档 Core v4.5.3 保持不变。`check-version`、Core 回归、bundle、导入器和包清单验证用于确认行为与发布入口一致。

同日 Core 回归修复：补齐 `view-transition-group-nearest`、`view-transition-group-*` 和 `view-transition-types-*` 的正式解析映射，确保文档示例与运行时一致。

同日视觉夹具切片：补齐 `qa-smoke.html` 与 `qa-regression-4.html`，两者均加载当前 Core、声明 viewport 并覆盖静态原子类，使 `check:visual` 具备稳定输入。

同日暗色迁移切片：Core 新增默认关闭的 `darkMapping` 配置。对 `map` 中明确列出的历史颜色类生成 `.dark` 与 `prefers-color-scheme: dark` 覆盖，支持透明度后缀、状态/响应式包装和边框方向；目标必须是 `theme.semantic` 角色，显式 `dark:` 变体优先。同步公开类型、主题文档、README、skill 与 Core 回归；未映射的旧类继续保持原义。

2026-10-16 输入组件切片：Select 与 NumberInput 增强样式接入现有 componentPresets.ui=semantic 和七个角色，涵盖搜索、选中、焦点、禁用、只读与快捷步进。保留 legacy，body 面板沿页面继承；同步可运行组合示例、配置摘要与 skill。浏览器基线发现 Select 稳定句柄断言失败，源码尚未实现共享栈/ARIA/远程取消契约，后续独立修复；本轮不将该旧回归记为通过。

### E2. 扩展现有 tokens 工具

2026-10-16 主题契约修复：浏览器复核确认历史映射遗漏主题节点自身、dark-media 字符串被误作选择器、字号同名令牌可能误加颜色。现已使用低权重主题条件覆盖自身和后代、恢复媒体规则包装、按实际解析属性校验映射并使旧缓存失效；新增 Core/压缩/Full/静态 CSS 与冷热缓存浏览器检查。Table 补齐 uiPreset 中已有正文/表头/空与加载状态/排序标记角色及工具栏焦点环。原主题测试聚焦不可聚焦 span 的问题改为验证真实刷新按钮；键盘排序和请求取消继续列为后续工作。

现有 bridge 已支持颜色、间距、圆角、字体族和 semantic 导入/导出。5.0 扩展别名引用解析、循环引用诊断、完整路径和类型检查，增加 typography、shadow、duration/easing 等复合令牌。主题模式采用明确的 JquanUI 扩展约定并记录支持范围。

先做 round-trip 和失败案例测试，避免把“支持部分 token 字段”表述为完整规范支持。

### E3. 类型覆盖和 IDE 服务
