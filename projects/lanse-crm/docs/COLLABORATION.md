# 客户跟进与团队协作

入口为 `index.html`；保持原有 Core、Data、Table、Pagination、Msg、Export 引入顺序。新增页面使用 ES module `src/collaboration.js`，不新增组件依赖、业务请求或页面 CSS。首次访问默认为白色亮色；有效的 `lanse-theme` 偏好优先，非法值回退亮色。首次渲染前即设置主题及 theme-color。

## 客户跟进

在「客户跟进」列表新建，或在客户、联系人、商机详情点击「记录跟进」。字段包括主题、客户、联系人、商机、沟通方式、日期、负责人、沟通结果、下次跟进日期、正文。客户和正文必填，联系人/商机可选且必须属于客户，切换客户时重新筛选可选记录。下次日期不得早于本次日期。

结果状态：待继续跟进、已达成共识、暂无意向。沟通方式：电话、微信、邮件、现场拜访、线上会议、其他。列表复用 Table/Pagination，支持搜索正文/客户、状态/负责人筛选、排序、分页、导入、导出和批量删除。详情显示完整正文及关联客户、联系人、商机；新增/修改同时写入客户操作时间线。

填写下次日期后，详情的「生成下次跟进任务」创建关联任务，沿用客户、负责人、正文与日期；重复点击返回已有任务。任务建立后，排期与完成状态在任务详情维护，修改原跟进日期不会重排已建立的任务。有任务引用的跟进不可直接删除，应先处理关联任务。任务与跟进在日历不重复展示。

旧版自由文本沟通在初始化时一次迁入：只迁移可解析到现有客户的沟通日志，保留旧日志、业务集合和原文字；编号 `FUP-LEGACY-{log.id}`，设置项 `collaborationVersion: 1` 防重复。详情原有快速留言也写入结构化跟进，非客户关联实体仍保存普通操作留言。恢复演示数据会移除自建/历史迁移数据并恢复样例，保留设置及主题。

应用层最小示例：

```js
import { save, createFollowupTask } from './src/data.js';
const record = await save('followups', {
  name: '云栖科技 · 需求沟通', customerId: 'CUS-0001',
  contactId: 'CON-1', opportunityId: 'OPP-1001', channel: '电话',
  date: '2026-10-09', owner: '林知夏', status: '待继续跟进',
  nextDate: '2026-10-12', content: '客户已确认需求，下次提交实施排期。'
});
const task = await createFollowupTask(record); // 返回任务记录，重复调用复用已有任务
```

`save(key, input, originalId?)` 返回保存后的记录。`createFollowupTask(row)` 无日期时抛错，多集合写入经 `atomic` 快照恢复；`tasks.followupId` 为应用关联字段，不是新增 Data API。联系人/商机已有跟进引用时禁止更换客户。

## 站内信

收件箱、已发送、草稿、回收站均持久化。支持主题/正文/成员搜索、每页 8 封分页、仅未读、全部已读、单封读/未读、写信、回复、移除、恢复和永久移除。顶栏与侧栏显示当前成员真实未读数量；提醒弹窗同时保留任务入口。

发送必填收件人、主题、正文；收件人来自已启用团队成员，主题最多 200 字、正文最多 2000 字，关联客户可选。允许不完整草稿，编辑后发送会更新同一条草稿为已发送。已发送消息正文不再编辑，回复创建新消息并保存 `replyId`。正文按纯文本显示并转义 HTML。发件人取系统设置的当前演示成员。

推荐体验：林知夏写信给陈屿 → 切换系统设置当前成员为陈屿 → 打开收件箱回复 → 切回林知夏查看回复。全部发生在同一浏览器/origin，没有真实邮件或多人网络通讯。未保存的撰写内容关闭后丢弃，需点击「保存草稿」保留。

`messages` 集合字段：`id/name/content/sender/recipient/customerId/status/at/replyId`；`status` 为草稿/已发送；`readBy/trashedBy/hiddenBy` 为成员姓名数组。回收与永久移除只影响当前成员视图，另一位参与者的消息保留；未发送草稿永久移除时删除其记录。删除可删除的客户时，消息保留历史客户名并解除跳转关系。当前演示成员为预设四位，成员姓名作为信箱身份，不实现真实权限或成员更名迁移。

```js
import { saveMessage, unreadCount } from './src/collaboration.js';
const message = await saveMessage({
  name: '方案协作', content: '请协助确认实施排期。',
  recipient: '陈屿', customerId: 'CUS-0001'
}, null, null, true);
// saveMessage(values, draftId?, replyId?, send): Promise<消息记录>
// send=false 保存草稿；send=true 校验后发送；失败抛错。
const count = unreadCount(); // 当前成员未读、未回收、未永久移除的收件数量
```

## 日历、审批与知识库

- 日历：月历 42 格，前后月份/今天、选日、负责人筛选；汇总任务、拜访与会议、营销活动、待回款、尚未生成任务的下次跟进。已完成、已取消、已回款不进入待办日历。点击事件打开原记录，选日新增日程会带入日期。日历日期为本地业务日期，今天按 Asia/Shanghai 获取，不调用外部日历。
- 拜访与会议：独立 CRUD 列表，客户、日期、开始时间必填，地点/会议链接为纯文本；日程类型为客户拜访/线上会议/团队会议；已安排可完成或取消。状态为已安排/已完成/已取消。不实现参会邀请、时区协商、重复日程与冲突检测。
- 审批中心：聚合现有合同，支持审批中/已批准/已驳回/已签订/全部筛选，显示申请人、客户、金额；通过/驳回复用现有合同状态动作、确认和操作日志，详情可查看流程记录。审批完成即同步合同列表和报表，不另建审批状态副本。仍为单层前端审批演示。
- 知识库：复用标准 CRUD、搜索/筛选/导入导出；分类为销售话术/产品资料/服务指南/内部制度，正文纯文本并保留换行。草稿可发布、已发布可归档、归档可重新发布。不实现富文本、附件或远端全文搜索。

## 生命周期与验证

所有新增集合复用每集合 IndexedDB 持久化、CRUD 数据源、flush/close；已有工作空间首次升级只初始化缺少的集合。新实体纳入完整备份与演示恢复。`collaboration.state` 只保存当前视图（月/日期、文件夹、搜索和筛选），刷新后恢复业务数据，视图恢复默认。无新增计时器/全局组件实例；Table/Pagination 继续随路由销毁；消息与日历事件由 app 的既有委托处理，dialog 负责关闭和焦点。

协作专题验证包括首次亮色及主题持久化、原 17 个实体 CRUD、关联校验、旧沟通迁移及去重、下次任务去重、草稿保存/刷新/发送、切换成员收信/回复、读状态/回收恢复/永久移除、日历导航/新增/完成、合同审批联动、知识发布/归档及移动端溢出。制造扩展后的总实体数为 24，新增七类的验证另见 [制造说明](MANUFACTURING.md)。运行项目 `check`、`check:browser`、`build` 和独立 site 检查，根 `check:docs`。这里只记录实际通过的结果到 verification，不更改框架公共 API。
